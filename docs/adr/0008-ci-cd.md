# ADR 0008 : intégration et déploiement continus

Statut : accepté le 2026-10-19.

## Contexte

Exigences N1 à N4 et critères R5 et R6. Comptes disponibles : GitHub (dépôt public), Firebase et Vercel. Aucun push ni déploiement sans ton accord explicite.

## Options

| Déploiement | Pour | Contre |
|---|---|---|
| A. Intégration Git de Vercel (production sur `main`, prévisualisation sur chaque PR), plus une protection de branche sur `main` qui exige une CI verte | Aucun jeton Vercel dans GitHub ; prévisualisations gratuites | N4 repose sur la protection de branche |
| B. Déploiement par la CLI Vercel depuis GitHub Actions, après la CI | N4 strict | Un jeton Vercel de plus en secret GitHub |

## Choix

**CI sur GitHub Actions**, quatre jobs :
1. Qualité : ESLint, vérification des types, contrôle de structure (ADR 0009).
2. Tests : Vitest (unitaires et serveur), règles et routes contre les émulateurs Firestore et Auth. Java est installé avec un JDK 21 Temurin. La documentation officielle demande un JDK 11 ou plus ; le JDK 21 couvre aussi les versions récentes de la CLI.
3. Bac à sable : Playwright avec Chromium.
4. Secrets : gitleaks en binaire, en version fixée à l'étape 5. S'y ajoutent la détection de secrets et la protection au push de GitHub, que tu actives dans les réglages du dépôt.

**Déploiement** : option A, plus un job GitHub Actions qui déploie les règles et les index Firestore après une CI verte sur `main`. Ce job s'authentifie avec un compte de service, via `GOOGLE_APPLICATION_CREDENTIALS`. `firebase login:ci` est déprécié.

## Raisons

- Le flux par PR est le cœur de la CI/CD agentique (Q3) : j'ouvre la PR, la CI tourne, et ta validation de la fusion vaut accord de déploiement.
- On a moins de secrets à gérer qu'avec B.

## Secrets (jamais dans le dépôt ni dans le chat ; c'est toi qui les saisis)

| Où | Nom | Contenu |
|---|---|---|
| Vercel | `FIREBASE_SERVICE_ACCOUNT` | Compte de service d'exécution (lecture et écriture Firestore), en base64 |
| Vercel | `KEY_ENCRYPTION_KEY` | Clé maîtresse (ADR 0004) |
| Vercel | `NEXT_PUBLIC_FIREBASE_*` | Configuration client, publique |
| GitHub | `FIREBASE_DEPLOY_SERVICE_ACCOUNT` | Compte de service de déploiement, limité aux règles et aux index |

Les rôles exacts du principe du moindre privilège sont à vérifier à la création des comptes de service.

## Conséquences

- La protection de branche est un réglage du dépôt. Le 2026-10-19, tu m'as autorisé à configurer la CI/CD avec `gh` (protection de branche, workflows). Chaque push, y compris le premier, reste soumis à ton accord explicite.
- Les règles se déploient après le front. Tout changement de règles doit donc rester compatible avec la version précédente.
- La revue IA des PR est prévue en T2 (Q3).
